## 1. Общий стек и архитектурные принципы

* **Сборщик и Dev-сервер:** [Vite 7](https://vite.dev/) с плагином `@vitejs/plugin-react` и встроенным проксированием `/api` к FastAPI бэкенду.

* **Тестирование:** [Playwright](https://playwright.dev/) для End-to-End регрессионного тестирования интерфейса и доступности (a11y).

## 2. Структура и назначение компонентов

### 2.1. Входная точка: [`src/main.tsx`](file:///C:/Users/akbar/.gemini/antigravity/scratch/aka/src/main.tsx)

---

### 2.2. Главный координатор: [`src/App.tsx`](file:///C:/Users/akbar/.gemini/antigravity/scratch/aka/src/App.tsx)
Компонент оркеструет все экраны, хранит главное состояние осмотра и управляет сетевыми запросами к API.

#### Основные внутренние подкомпоненты:
1. **`Brand`**: Логотип с отпечатком пальца (`Fingerprint`) и фирменной типографикой `carprint.`.
2. **`PhotoInput`**:
   * Полнофункциональная зона Drag-and-Drop загрузки снимка.
   * Валидация формата (JPG, PNG, WebP) и размера (до 8 МБ).
   * Предпросмотр миниатюры, отображение имени файла и размера, кнопка очистки/замены.
3. **`Workspace`**:
   * Сердце студии верификации.
   * Содержит селектор деталей `PartAtlas`, панель пресетов `PRESET_SCENARIOS`, две карточки загрузки `PhotoInput`, индикаторы прогресса и кнопку отправки на сопоставление.
   * Поддерживает отмену сетевых запросов через `AbortController` (с таймаутом 60с для сравнения и 30с для пресетов).
4. **`Comparison`**:
   * Выводит результаты вычислений алгоритма компьютерного зрения:
     * Количество inliers (согласованных точек).
     * Медианную ошибку репроекции (в пикселях).
     * Процент покрытия поверхности (Convex Hull).
     * Время инференса на сервере.
   * Переключение между 3 режимами визуализации доказательств:
     * **Matching points** — линии соответствия дескрипторов SIFT (`drawMatches`).
     * **Aligned overlay** — проективное наложение с интерактивным ползунком-шторкой (Before/After slider).
     * **Damage timeline** — детальный осмотр дефектов через `DamageTimelineView`.
   * Кнопка вызова официального сертификата проверки (`onOpenCertificate`) и кнопка выгрузки чистого технического JSON-отчёта.
5. **Вспомогательные лендинг-секции**:
   * `ValueStrip` — плашка ключевых ценностных преимуществ.
   * `Process` — 5 проверяемых этапов пайплайна (Capture Gate → Part Atlas → Identity → Damage Timeline → Audit).
   * `Solutions` — целевые B2B-сценарии (дилеры, trade-in, каршеринг/прокат, страхование).
   * `FAQ` — аккордеон с техническими ответами (работа в темноте, желтый свет, грязь, различие одинаковых Cobalt, правовые ограничения).

### 2.3. Интерактивная 2D-схема кузова: [`src/PartAtlas.tsx`](file:///C:/Users/akbar/.gemini/antigravity/scratch/aka/src/PartAtlas.tsx)
* **Назначение:** Разделение геометрии автомобиля на независимые плоскости деталей, предотвращая ошибки проективной геометрии 3D-поверхности кузова.
* **Техническая реализация:**
  * Интерактивная векторная карта (SVG) автомобиля с сеткой и анимацией сканирующего лазерного луча (`radarSweep`).
  * Зоны деталей: `left_front_door` (передняя дверь), `left_rear_door` (задняя дверь), `front_bumper` (передний бампер), `rear_bumper` (задний бампер), `front_left_wheel` / `rear_right_wheel` (колеса), `hood` (капот).
  * При клике на деталь обновляется состояние `selectedPart`, запускается пульсирующий маяк (`pulseBeacon`) и подгружаются CAD-допуски детали и её расчётный вес различимости $w(f)$.

### 2.4. Модуль детекции повреждений: [`src/DamageTimelineView.tsx`](file:///C:/Users/akbar/.gemini/antigravity/scratch/aka/src/DamageTimelineView.tsx)
* **Назначение:** Реализация концепции «Было / Стало» в соответствии с разделом 8 технического описания.
* **Ключевой функционал:**
  * **Визуализация наложения:** Отображение совмещённого изображения с рамками дефектов.
  * **Микроскопическая лупа 4x Zoom:** Плавающий круглый визир, следующий за курсором мыши/тачем:
    $$\text{bgX} = \frac{x}{\text{width}} \times 100\%, \quad \text{bgY} = \frac{y}{\text{height}} \times 100\%$$
    Позволяет эксперту попиксельно изучить текстуру микроцарапины и шагрень краски.
  * **Реестр аномалий (Damage Ledger):** Карточки найденных дефектов с оценкой дистанции Чамфера (в мм), площади в пикселях и степени тяжести (`MINOR` / `MODERATE`).
  * **Телеметрия Quality Gate:** Реальные карточки качества обоих фото (резкость по Лапласиану, средняя яркость, процент бликов) с практическими советами по пересъёмке.

### 2.5. Аудиторский сертификат: [`src/AuditCertificateModal.tsx`](file:///C:/Users/akbar/.gemini/antigravity/scratch/aka/src/AuditCertificateModal.tsx)
* **Назначение:** Формирование официального юридически корректного протокола осмотра доказательств.
* **Содержимое:**
  * Идентификатор сессии (криптографический nonce), метка времени ISO 8601 UTC, ID сертифицированного аудитора.
  * SHA-256 хеши исходных файлов для защиты цепочки хранения (Chain of Custody).
  * Математический аудит совмещения (inliers, reprojection error, LLR).
  * Таблица обнаруженных повреждений с координатами bounding box.
  * Фирменная печать CarPrint Verified и правовой отказ от ответственности.
* **Печать:** Стилизован под печать через CSS `@media print` — открывает системный диалог печати браузера для сохранения готового PDF-документа.

## 3. Управление состоянием и жизненный цикл данных

### 3.1. Жизненный цикл фотографий (Memory Safety)
* При выборе файла через диалог или drop генерируется Blob URL:
  ```ts
  const url = URL.createObjectURL(file);
  ```
* Во избежание утечек оперативной памяти все временные URL принудительно очищаются при замене фото, сбросе (`reset`) или размонтировании компонента:
  ```ts
  useEffect(() => () => {
    photosRef.current.forEach(p => p && URL.revokeObjectURL(p.url));
  }, []);
  ```

### 3.2. Взаимодействие с API
* **Запрос сопоставления (`compare`)**:
  * Формирует `FormData` с полями `reference`, `current` и `part_id`.
  * Отправляет `POST /api/compare` с таймаутом 60 секунд.
  * После получения ответа автоматически плавно скроллит пользователя к результатам (`resultRef.current?.scrollIntoView`).
* **Пресеты (`loadPreset`)**:
  * Загружает эталонные изображения с сервера (`/api/presets/{id}/reference` и `current`).
  * Преобразует Blob в объекты `File` и наполняет ими интерфейс без необходимости ручной загрузки пользователем.

## 4. Дизайн-система и стили (`styles.css`)

### 4.1. Цветовая палитра
* **Тёмный телеметрический фон:** `#060911`, `#0d131f`, `#1e293b`.
* **Светлый фон основного контента:** `#f7f8f4`, `#ffffff`.
* **Акцентный Cyber-Lime:** `#d3f880`, `#10b981` (статус успеха, согласованные точки).
* **Electric Cyan:** `#00f0ff` (визиры, фокус лупы, радарные линии).
* **Warning Amber:** `#d97706` (предупреждения качества, серийные детали).
* **Danger Red:** `#ef4444`, `#dc2626` (новые повреждения на выдаче).

### 4.2. Ключевые CSS-анимации
* `@keyframes radarSweep`: горизонтальная лазерная полоса сканирования, проходящая по чертежу автомобиля в Part Atlas.
* `@keyframes pulseBeacon`: пульсация контрольной точки на выбранной детали кузова.
* `@keyframes pulseReticle`: переливающаяся рамка вокруг обнаруженного дефекта.

### 4.3. Адаптивность и доступность
* Тщательно протестировано на брейкпоинтах **320px, 390px, 768px, 1024px, 1440px** — полное отсутствие горизонтального переполнения (`scrollWidth <= window.innerWidth`).
* Поддержка навигации с клавиатуры (`Escape` закрывает меню, `Tab` и стрелки управляют шторкой сравнения).
* Соблюдение системной настройки `prefers-reduced-motion: reduce`.
