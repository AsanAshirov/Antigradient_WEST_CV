# CarPrint — Verification Intelligence

Адаптивный сайт и работающий прототип геометрического сравнения двух фотографий автомобиля. Обновлённый интерфейс: светлый фон, графитовая типографика, лаймовые акценты и студия сравнения с пошаговой загрузкой, подсказками и очисткой снимков. Весь сайт, сообщения API и экспортируемые отчёты — на английском языке. Вступительная анимация больше не задерживает доступ к содержимому.

**Режим проекта: Partner Product.** Предлагаемый владелец процесса — отдел сервисной приёмки дилера. Сценарий — сравнение состояния при приёмке и выдаче. Это предлагаемая модель внедрения, а не заявление о заключённом партнёрстве.

## Запуск

Требования: Node.js 24, npm 11, Python 3.12. GPU и ключи внешних API не нужны.

```bash
cd /workspace/aka
bash scripts/setup.sh
npm run dev
```

Frontend: порт 5173. API: порт 8000. Vite проксирует `/api` к Python. `Ctrl+C` завершает оба процесса. Для другого расположения репозитория достаточно перейти в его корень: скрипты сами определяют рабочую директорию.

Работа в облачной задаче уже изолирована: используйте существующий checkout, не создавайте worktree без явного запроса.

## Возможности

- Первый экран: фоновое видео из предоставленных пользователем `0.MOV` и `1.MOV`, объединённых в этом порядке в `public/videos/hero-sequence.mp4` (H.264, 24 fps, 10,08 с). Автозапуск без звука, повтор 0 → 1 → 0 → 1, кнопка паузы. При `prefers-reduced-motion` показывается постер с возможностью включить видео вручную. Ролики — иллюстрация концепции, не результат обработки CarPrint. Исходные MOV не изменены.

- Адаптивный лендинг, интерактивные зоны осмотра, шаги процесса, мобильное меню, FAQ.
- Уважение `prefers-reduced-motion`, клавиатурная навигация, подписи элементов.
- Загрузка и перетаскивание двух JPG/PNG/WebP до 8 МБ каждый; не менее 96 × 96 пикселей, до 20 мегапикселей при декодировании.
- SIFT → подбор дескрипторов → ratio test → уникальные соответствия → RANSAC.
- Визуализация реальных геометрически согласованных точек, медианная reprojection error и число inliers.
- Совмещение изображений и интерактивный разделитель, если геометрия достаточно устойчива.
- Экспорт JSON-отчёта с SHA-256 исходных файлов, предупреждениями, версией алгоритма и измеренным временем.
- Честные состояния ошибки, недостаточных доказательств и недоступности сервера.

API выполняет обработку на CPU сервера, уменьшает длинную сторону до 1200 пикселей и использует два потока OpenCV. Время в интерфейсе измеряется для конкретного запроса, включая подготовку изображений результата, без сетевой передачи. Декодирование и анализ выполняются в памяти, фотографии не отправляются внешним провайдерам. Загрузка multipart-запроса может использовать временный файл Starlette; после запроса он закрывается и удаляется. Базы клиентов и постоянного хранилища нет.

## Ограничения прототипа

Это реальный baseline компьютерного зрения, **не обученная модель проверки физической идентичности**. Геометрия серийных деталей может совпадать у разных машин. Поэтому итог всегда `REVIEW`: специалист должен изучить индивидуальные следы и независимые идентификаторы. `MATCHED` описывает только геометрическое соответствие. Числа inliers и покрытия не являются вероятностью идентичности.

Пороги (12 inliers, 2% покрытия, ошибка до 4 px) — предварительная эвристика для показа совмещения; они не откалиброваны на автомобилях. Не реализованы SAME/DIFFERENT, сегментация повреждений, история осмотров в БД, VIN/OCR, PWA-камера, аккаунты и контроль происхождения фото. Лендинг описывает продуктовую концепцию, FAQ разграничивает реализованные функции и следующие этапы.

«Использовать пример» загружает AI-изображение автомобиля и его повёрнутую/изменённую по яркости копию. Оба файла проходят тот же реальный API. Это синтетический пример регистрации, а не доказательство точности на разных осмотрах. Приложение также принимает собственные фотографии. Валидации на реальных автомобилях ночью, в дождь и на одинаковых экземплярах пока нет. Стоимость осмотра и бизнес-эффект не измерены и не заявляются.

## Проверки

```bash
npm run build
.venv/bin/python -m pytest server/test_app.py -q
# При запущенном npm run dev и установленном Chromium:
npm run test:e2e
```

Браузерные тесты используют `/usr/bin/chromium` в Linux и установленный Playwright Chromium на остальных платформах. Другой путь задаётся через `CHROMIUM_PATH`. API-тесты проверяют известное преобразование, несвязанные изображения, пустые кадры, повреждённые/неподдерживаемые файлы, предел размера и реальную обработку синтетического примера. E2E проверяют загрузку, сравнение, разделитель, отчёт, ошибки, мобильную навигацию и отсутствие горизонтального переполнения.

## Production

```bash
npm run build
.venv/bin/python -m uvicorn server.app:app --host 0.0.0.0 --port 8000
```

После сборки FastAPI раздаёт и `dist`, и API с одного адреса. Перезапустите сервер после первой сборки, чтобы подключилась раздача статики. Есть Dockerfile для платформ, поддерживающих контейнеры:

```bash
docker build -t carprint .
docker run --rm -p 8000:8000 carprint
```

Порт можно переопределить переменной `PORT`. Health check: `/api/health`. Для публичного размещения нужны HTTPS и ограничения размера/частоты запросов на ingress; приложение пока предназначено для демо, без авторизации. Ограничьте тело multipart-запроса на ingress до 18 МБ. Проверка 8 МБ на файл выполняется после multipart parsing. Публикация не выполнена: требуется аккаунт/проект хостинга. Dockerfile не означает, что контейнер уже был собран или развёрнут.

По условиям хакатона публично доступный frontend и backend должны развёртываться из предоставленного репозитория. Укажите фактический commit в подаче, соблюдайте дедлайн и декларируйте использование AI-помощника и время создания. Никаких заявлений о том, что этот код создан командой во время финала, репозиторий не делает.
